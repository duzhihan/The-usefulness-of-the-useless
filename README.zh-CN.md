> **DiTing（谛听）是一个 AI 思考协议（skill）。当你被一个模糊、纠结的问题困住，翻来覆去也想不清楚时，它不直接给你答案，而是用六轮"边问边确认"的方式，陪你一步步把它想透，最后交给你一个自己拍过板、敢承担后果的决定。**

[English](README.md) | **简体中文**

## 从一个场景说起

设想你正坐在屏幕前，把一个纠结了好几天的问题敲进对话框——

**"我到底该不该转行？"**

几秒后，AI 回了一段漂亮的答案，还附了三条理由。

但你看完，心里反而更乱了。

不是答案不对。是那个答案**不是你的**。你跳过了"把它想清楚"的过程，所以它说服不了你——更说服不了那个将来会半夜醒来、怀疑自己选错路的人。

这，就是 DiTing 要解决的、那件具体的事。

---

## 你缺的不是答案，是"想清楚"

大多数 AI 交互是一问一答：你问，它答，思考这一步被跳过了。

可对那些真正难的问题——要不要转行、要不要读博、这个选题值不值得做——你缺的根本不是一个答案。

你缺的是两样东西：

1. **清晰度**——你到底卡在哪、最怕什么、最看重什么。这些你心里都有，只是一直说不出口。
2. **认同度**——一个你愿意承担后果的决定。"别人替我选的"，再好也会后悔；"我自己想出来的"，再难也扛得住。

一句话：**你不是不会选，是还没把自己"想清楚"。**

---

## 常规办法，为什么都差一步

面对"想不清楚"，市面上通常有几条路——但都差那么一步：

- **直接问大模型**：它给你一个答案，甚至很好。但答案建立在"替你思考"之上，跳过你的过程，所以你拿到结论也不敢信。
- **套一个"深度思考"提示词**：让它"一步一步想"。但它一口气输出、从不回头跟你确认，你真正在意的那个点，它可能压根没碰到。
- **第一性原理**：把问题拆到最底层，很好——但它只给你一种镜头。它看不见"你的偏好"，因为偏好不是拆出来的，是**问**出来的。

它们的共同缺口是：**都在"替你生产答案"，没有谁在"帮你发现自己"**。

而这一步，恰恰是决定你事后会不会后悔的那一步。

---

## 谛听换了一个前提：答案不在模型里，在你心里

谛听能补上这一步，是因为它换了一个理论前提：

> 传统 AI 默认：**答案在模型里，你缺，所以给你。**  
> 谛听默认：**答案在你心里，只是还没被说出来，所以它要做的，是帮你把它"生出来"。**

这不是拍脑袋，而是五条理论支柱撑起来的：

| 理论            | 一句话意思              | 它决定了谛听的哪个设计           |
| ------------- | ------------------ | --------------------- |
| 波兰尼 · 默会知识    | 你知道的，比你能说出来的多      | 所以要靠"追问"，把说不出口的逼出来    |
| Slovic · 偏好建构 | 偏好不是现成的，是问着问着才成形   | 所以每个"确认点"都在帮你建构，而不是收集 |
| 苏格拉底助产术       | 老师不灌输，只帮心里的东西"生出来" | 所以全程都是"问"，不是"答"       |
| 决策后悔理论        | 后不后悔，看过程是不是你自己选的   | 所以每一环都要你亲自拍板          |
| 视角主义          | 换视角不是找唯一答案，是看见盲区   | 所以有"可插拔思维模式库"         |

一句话：**DiTing 的角色不是"给你答案的老师"，而是"帮你接生的助产士"。**

## 它怎么陪你"想清楚"：六环引擎

![六环认知引擎工作流程](assets/readme/workflow.svg)

DiTing 把"想清楚"拆成六个环，你带着任何一个模糊的问题进来，跟着走一圈：

1. **锚定** —— 先把你真正卡住的点问出来：你到底怕什么、要什么。
2. **对抗** —— 站在反面，把它的漏洞挑一遍（只问一个关键问题，你答了才继续）。
3. **拆解** —— 把大问题拆成几个能分别想清楚的小块。
4. **表达** —— 给你几种语气，选一种锁定基调。
5. **成型** —— 汇成完整方案，每一条都标"这条结论是怎么来的"。
6. **验证** —— 用轻量 3 项 / 重量级 5 项给方案做压力测试，打个韧性分。

贯穿全程的三条纪律：

- **七确认点**：每一环结束都停下来问"这样对不对"，绝不一口气跑完。
- **一次一问**：一次只问一个问题，你答了再往下；九成五把握，就停。
- **模式可插拔**：八张思维模型卡（求是、费曼、芒格……），只借"怎么想"，不扮演人。

走完这一圈，你得到的不是一段建议，而是**一份你亲自确认过的决定 + 它的来龙去脉 + 一份验证报告**。

## 和别的工具比，它到底多加了什么

拿同一个问题来比："我该不该转行？"

|         | 直接问大模型   | 套"深度思考"提示词   | **DiTing**              |
| ------- | -------- | ------------ | ----------------------- |
| 它给你什么   | 一个答案     | 一段长推理        | **一次你亲自拍板的决定**          |
| 答案是谁的   | 模型的      | 模型的          | **你的**                  |
| 你参与了吗   | 没有，思考被跳过 | 基本没有，它一口气输出  | **每一环都停下来跟你确认**         |
| 结束后你确定吗 | 不确定，还会纠结 | 未必，它可能没碰到你的点 | **确定——是你一步步推出来的**       |
| 下次再遇到   | 从零开始     | 从零开始         | **越用越会想（轨迹/画像/视角银行沉淀）** |

DiTing 没有在"更聪明"上和它们较劲，它加的是别的东西：

- **确认点反馈环**：你每选一次，它回你一句"你选这个，说明你更看重……"——把你的偏好照出来。
- **双级验证**：结论要经得起挑刺，才交到你手上。
- **长期沉淀**：思维轨迹、偏好画像、视角银行，全存你本地，越用越准。
- **理论化的帮手**：面对研究问题，它把你的直觉逼成"可被反驳的命题"，而非塞给你一个结论——这正是发现隐藏理论的关键一步。

## 它能用在哪些地方

| 场景       | 例子                         |
| -------- | -------------------------- |
| **重大抉择** | 转行、读博、要不要分手……凡是"选了就要承担很久"的 |
| **学术研究** | 选题是否值得做、论点能否成立、如何自我反驳；更关键的是，把零散的直觉、文献与经验梳理成可论证的理论脉络，并在对抗性检验中暴露被忽略的隐藏维度 |
| **写作创作** | 大纲怎么搭、语气怎么定、方向反复拿不准        |
| **职场实务** | 方案怎么论证、冲突怎么谈、谈判怎么出牌        |
| **自我成长** | 我到底看重什么、复盘上一次决定            |

**边界一句话：凡"没有标准答案、但必须你自己想清楚并承担后果"的问题，都是 DiTing 的主场。**

## 学术研究：它怎么帮你"想"出一个隐藏的理论

对人文社科研究者而言，DiTing 最被低估的价值，不在"帮你拍板"，而在**陪你把研究直觉想透、想清楚，并逼出一个可被讨论、可被反驳的理论命题**。

研究里最常见的困境，不是"没想法"，而是：你在田野或文献里撞见了一个反常，直觉告诉你"标准解释讲不通"，可它停在你脑子里，只是一团模糊的不适——写不进论文，也不敢拿去和同行争。你要的不是更多文献，而是一个能陪你**梳理、追问、对抗**的对手。

下面用六环，走一遍一个一般化的研究场景（不指向任何具体个人）：

> **研究者的直觉**：我做社区研究时发现，一些完成更新改造的老旧小区，老住户之间的走动反而比改造前更密了。这和"更新必然让原居民疏远"的常识相反，我总觉得这背后有文章，但说不清、写不出。

- **锚定** —— 真正卡住的不是一个案例，而是"空间更新到底改变了什么"这个**机制问题**：你是在问"物理环境塑造交往"，还是在问"符号化空间重塑身份归属"？这一问，把含糊的"反常"收敛成一个可被研究的命题。
- **对抗** —— 若城市更新必然瓦解原居民的社会网络（士绅化理论的经典论断），那这个小区就是反例；可经验上，改造后的公共空间确实多了人停留。矛盾卡在哪？这一击，让你看见直觉里真正坚硬的那块。
- **拆解** —— 把"更新效应"拆成两层：**（1）空间的消费化**（引进商铺，挤占生活）；**（2）空间的生活化**（保留菜场、棋牌角，维持日常）。这是你原没做、却决定成败的区分。
- **表达** —— 锁定论述基调：冷静、论证式、留有余地。
- **成型** —— 命题浮现：更新不一定驱逐邻里；当改造保留"生活性"而非纯"消费性"时，空间的可见度反而激活了原本沉睡的邻里纽带。每条结论都标着"它从哪一步来"。
- **验证** —— 林奇假设扫描：这个命题扛得住"更新终将置换人口"的反驳吗？韧性评分 7.5/10，并提示补一个微观机制（可见度如何具体转化为走动频率）。

走完这一圈，你拿到的不是"一个现成答案"，而是**一个你亲自推出来、知道边界在哪、也敢拿去争论的理论命题**——这正是人文社科研究里最珍贵的一步：把朦胧的直觉，变成可以进入公共讨论的知识。

## 三分钟上手

### 安装

```bash
# 方式 A：把 skill 复制进你的智能体 skill 目录（WorkBuddy / Claude 等）
cp -r skill/thinking-protocols ~/.workbuddy/skills/

# 方式 B：克隆后软链接
git clone https://github.com/<your-name>/DiTing-Protocol.git
ln -s "$(pwd)/DiTing-Protocol/skill/thinking-protocols" ~/.workbuddy/skills/thinking-protocols
```

### 首次使用

1. 把 `data/_templates/` 下的空模板复制到 `data/traces|profiles|perspectives/`；
2. 用任意一句唤起它：`帮我理清思路` / `我想把这件事想透` / `先问问我，别急着写`。

### 一个最小对话（一般化）

```
你:    我在一份稳定但没成长的工作里待了三年，想转行又怕风险，拿不定主意。
谛听:  你更怕"转了之后更差"，还是"不转一辈子不甘心"？
你:    其实更怕后者。
谛听:  （锚定）那真正的主矛盾，是"风险不可知"，还是"自我认同危机"？
你:    是自我认同。
谛听:  （对抗）如果"先做低风险的副业试探"这条路成立，它最弱的反对意见是什么？
...
谛听:  （验证 → 交付）方案 + 每条结论的来源 + 验证报告。
       → 回显：你选了"先做低风险试探"，说明你更看重"可逆性"。
```
